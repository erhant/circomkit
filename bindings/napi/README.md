# circomkit

The `circomkit` npm package — a Circom development & testing toolkit. It is
**both** a native library (napi-rs bindings to the Rust orchestrator) **and**
the `circomkit` CLI (the Rust binary, shipped inside the same package).

- `import { Circomkit } from "circomkit"` — the library.
- `bun add -g circomkit` (or `npm i -g circomkit`), then `circomkit …`; `bunx circomkit` for one-offs — the CLI.

`circom` and `snarkjs` must be installed and on your `PATH` at runtime.

## Requirements

- Node.js ≥ 20
- Rust ≥ 1.88 and a working linker (to build the addon)
- `circom` and `snarkjs` on `PATH` (runtime)

## Build

```sh
cd bindings/napi
bun install
bun run build       # napi build --release → circomkit.<platform>.node + index.js + index.d.ts
```

> Use `bun run build` (not `bun build`, which invokes Bun's own bundler).

## Usage

```ts
import { Circomkit } from "circomkit";

// Load from a circomkit.json, or from a JSON config string:
const ck = Circomkit.fromFile("./circomkit.json");
// const ck = Circomkit.fromConfig(JSON.stringify({ /* ... */ }));

ck.compile("multiplier_3");

// Inline input signals are passed as a JSON string:
const input = JSON.stringify({ in: [3, 5, 7] });
ck.witness("multiplier_3", "my_input", input);

ck.setup("multiplier_3"); // auto-downloads PTAU for bn128
ck.prove("multiplier_3", "my_input", input);
const ok = ck.verify("multiplier_3", "my_input");

const info = ck.info("multiplier_3"); // { wires, constraints, primeName, ... }
```

## API

`Circomkit.fromFile(path)`, `Circomkit.fromConfig(json)`, and the instance methods: `instantiate`, `compile`, `info`, `clear`, `ptau`, `setup`, `vkey`, `contract`, `witness`, `prove`, `verify`, `calldata`, `loadInput`. Circuit inputs cross the boundary as JSON strings; path-returning methods return the path as a string. See `index.d.ts` (generated by the build) for exact types.

## How the CLI ships in the same package

`bin.js` is a tiny launcher (no CLI logic) that execs the native `circomkit` binary. The binary is the Rust `circomkit-cli` crate, bundled per platform:

- The library's `.node` addon is published in per-platform packages (`circomkit-<platform>`, wired as `optionalDependencies`) by napi-rs.
- CI also builds `circomkit-cli` for each target and drops the binary into the matching platform package via `scripts/bundle-cli.mjs`.
- At runtime, `bin.js` resolves the installed platform package and execs its bundled binary, so `circomkit …` runs the real Rust CLI.

### Publish flow (per target, in CI)

```sh
# library addon (.node)
napi build --release --target <rust-triple>
cargo build --release -p circomkit-cli --target <rust-triple>

# scaffold npm/<key>/ packages
napi create-npm-dirs
# move .node into npm/<key>/
napi artifacts
bun scripts/bundle-cli.mjs <platform-key> target/<rust-triple>/release/circomkit

# then: napi prepublish -t npm  (publishes main + platform packages)
```

The non-npm channels (GitHub Releases, `curl | sh`, Homebrew, `cargo install circomkit-cli`) are handled separately by [`dist`](https://opensource.axo.dev/cargo-dist/) (config in the workspace `Cargo.toml`).
